# Этап 4. Интеграция программного модуля расчёта стоимости

## Модуль `rental_cost`

Отдельный пакет в корне проекта. Он не использует Django и базу данных, поэтому его можно
проверить, запустить и подключить отдельно от приложения.

| Файл | Назначение |
|---|---|
| `rental_cost/calculator.py` | Расчёт: функции `calculate_cost()` и `calculate_total()`, класс результата `CostResult`, ошибка `CostCalculationError` |
| `rental_cost/__main__.py` | Запуск из командной строки: `python -m rental_cost --type Горный --days 4 --price 800` |
| `rental_cost/tests.py` | Модульные тесты расчёта (12 тестов) |

**Входные данные:** тип велосипеда, продолжительность проката (целое число суток ≥ 1), базовая стоимость суток (> 0).

**Результат:** итоговая стоимость (`CostResult.total`), а также промежуточные величины для показа
пользователю: базовая стоимость, размер и сумма скидки.

**Правило:** `итог = базовая_цена × сутки`, при прокате от 3 суток — скидка 10 %, округление до копеек.
Некорректные данные (пустой тип, 0 суток, цена ≤ 0, не число) — понятная ошибка `CostCalculationError`.

```python
from decimal import Decimal
from rental_cost import calculate_cost

result = calculate_cost('Горный', 4, Decimal('800'))
result.total            # Decimal('2880.00')
result.discount_amount  # Decimal('320.00')
```

## Интеграция с приложением

```
Форма проката ──► rentals/services.py ──► pricing/services.py ──► rental_cost.calculate_cost()
 (велосипед,       create_rental /          переводит данные БД:      (тип, сутки, базовая цена)
  даты)            update_rental            тип → название,                      │
                                            даты → сутки,                        ▼
                                            цена типа                     итоговая стоимость
                                                                                 │
        rentals_rental.total_cost ◄──── сохраняется ◄────────────────────────────┤
        карточка проката, расчёт в форме ◄── показывается ◄──────────────────────┘
```

- `pricing/services.py` — связующий слой (адаптер): берёт из базы тип велосипеда и его базовую
  цену, считает количество суток по датам и передаёт эти три значения в модуль.
- `rentals/services.py` — при оформлении и редактировании проката сохраняет итог модуля в
  `total_cost`. Ошибка модуля превращается в сообщение «Не удалось рассчитать стоимость: …», прокат не создаётся.
- Карточка проката и предварительный расчёт в форме (`/rentals/estimate/`) показывают
  разбивку из того же результата модуля, поэтому сумма на экране совпадает с сохранённой.
- Команда `seed` тоже считает стоимость тестовых прокатов через модуль.
